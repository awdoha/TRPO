# Практическая работа №3. Работа с 2D-графикой в Windows Forms

Костин Даниил Антонович

## Формулировка задания

Требуется разработать WinForms-приложение для работы с двумерной графикой. Приложение
позволяет:

- добавлять точки по щелчку мыши в специальной области рисования;
- перетаскивать уже поставленные точки мышью;
- по набору отмеченных точек строить графические фигуры разными способами (замкнутая
  кривая, ломаная/многоугольник, кривые Безье, залитая замкнутая кривая);
- часть функциональности зависит от индивидуального варианта.

Общие требования к приложению:

1. Форма с заданными параметрами: размер, положение на экране при запуске,
   ограничения `MinimumSize`/`MaximumSize`.
2. Набор кнопок управления: «Точки», «Параметры», «Кривая», «Ломаная», «Безье»,
   «Заполненная», «Движение», «Очистить» (плюс дополнительная кнопка «Сохранить»,
   необходимая для варианта — см. ниже).
3. Обработчики этих кнопок: включение/выключение добавления точек, открытие окна
   параметров, выбор способа отображения фигуры, включение/выключение движения,
   сохранение текущей фигуры, полная очистка.
4. Обработка клавиш: `Space` — движение, `+`/`-` — скорость движения, `Esc` — очистка,
   стрелки — сдвиг фигуры. Стрелки обязательно обрабатываются через переопределение
   `ProcessCmdKey`, остальные клавиши — через `KeyDown` (`KeyPreview = true`).
5. Перетаскивание точек мышью через `MouseDown`/`MouseMove`/`MouseUp`.
6. Анимация движения точек реализуется через `Timer`, при этом скорость точек
   задаётся величиной смещения за один тик, а не изменением интервала таймера.

## Мой вариант

Вариант вычисляется по формуле `V = (int(c1) + int(c2)) % 10`, где `c1` и `c2` — первые
буквы имени и фамилии (по условиям практики — инициалы: `К` для Kostin и `Д` для Daniil,
взятые в латинской раскладке как `K` и `D`).

`int('K') = 75`, `int('D') = 68`. Сумма `75 + 68 = 143`. `143 % 10 = 3`.

Таким образом, **V = 3**, и в задании этому варианту соответствуют функции **Д4, П2, С1,
Р1**:

- **Д4 — режим «Движение».** В этом режиме все точки на форме одновременно смещаются, у
  каждой — своё случайное направление и скорость, выбранные один раз в момент включения
  движения и не меняющиеся сами по себе в дальнейшем. Особенность варианта: как только
  **любая одна** точка достигает края формы, направление меняют **все** точки сразу
  (а не только столкнувшаяся). В моей реализации это сделано физически точно: при выходе
  любой точки за границу по оси X у всех точек меняется знак горизонтальной составляющей
  скорости, при выходе по оси Y — у всех меняется знак вертикальной составляющей
  (а не берутся полностью новые случайные направления для всех точек).
- **П2 — окно «Параметры».** Отдельное модальное окно, в котором цвет точек и цвет
  линии/кривой выбираются из выпадающего списка (`ComboBox`) с предустановленными
  именами цветов — без системного `ColorDialog`.
- **С1 — сдвиг стрелками.** Нажатие клавиш-стрелок сдвигает всю фигуру (все точки) в
  соответствующую сторону. Эта функция не действует, пока включён режим движения (Д4).
- **Р1 — режим «Сохранение».** По нажатию отдельной кнопки «Сохранить» текущий набор
  точек вместе с выбранным способом отображения и текущими цветами фиксируется —
  переносится в список сохранённых фигур и продолжает отображаться на экране. Новые точки,
  добавляемые кликом после сохранения, образуют уже новую, отдельную фигуру и в состав
  сохранённой не входят.

## Реализация

### Структура проекта

- `Program.cs` — точка входа, запускает `MainForm`.
- `MainForm.cs` — главная форма со всей логикой приложения.
- `ParametersForm.cs` — дочернее модальное окно «Параметры» (П2).
- `Shape.cs` — enum `ShapeMode` (способ отображения: без фигуры, кривая, ломаная, Безье,
  заполненная) и класс `Shape` — сохранённая фигура (точки + режим + цвета).
- `DrawingPanel.cs` — наследник `Panel` с включённой через `SetStyle` двойной
  буферизацией, чтобы анимация в режиме движения не мерцала.

### Архитектура и ключевые решения

**Хранение точек.** Есть `List<Point> _currentPoints` — точки текущей, ещё не
зафиксированной фигуры, и `List<Shape> _savedShapes` — уже сохранённые фигуры (функция
Р1). Каждая `Shape` хранит собственную копию списка точек, поэтому дальнейшее
редактирование текущей фигуры никак не затрагивает уже сохранённые.

**Отрисовка (`DrawPanel_Paint` / `DrawShape`).** Сначала рисуются все сохранённые фигуры,
затем поверх — текущая. Для каждой фигуры сначала точками (`Graphics.FillEllipse`)
отмечаются узлы, затем, в зависимости от `ShapeMode`, вызывается:
`Graphics.DrawClosedCurve` (Кривая), `Graphics.DrawPolygon` (Ломаная),
`Graphics.DrawBeziers` (Безье) или `Graphics.FillClosedCurve` + `DrawClosedCurve`
(Заполненная).

**Кривые Безье.** `DrawBeziers` требует, чтобы количество точек было равно `4, 7, 10, ...`,
то есть `(n - 1)` кратно 3. Если пользователь отметил больше точек, но их число не подходит
под формулу, используется максимально возможное подмножество из первых точек — метод
`GetBezierSubset` вычисляет `usableCount = ((n - 1) / 3) * 3 + 1` и передаёт в
`DrawBeziers` только эти точки. Это осознанный выбор: он не блокирует построение кривой,
если пользователь поставил на 1-2 точки больше или меньше нужного количества.

**Параметры (П2, `ParametersForm.cs`).** Окно — обычный модальный `Form`
(`ShowDialog`) с двумя `ComboBox` в режиме `DropDownList` (нельзя ввести произвольный
текст), заполненными предустановленным списком имён цветов (`Color.FromName`), и двумя
цветными панелями-превью, которые обновляются по `SelectedIndexChanged`. При открытии окна
в комбобоксах заранее выбираются текущие цвета точек и линии.

**Движение (Д4).** При включении режима движения (`ToggleMovement` → `BuildMovingPoints`)
собирается единый список `MovingPoint`, объединяющий точки *всех* фигур — и текущей, и всех
сохранённых: каждый элемент хранит ссылку на список-владелец (`List<Point> Owner`), индекс
внутри него и вектор скорости `(Vx, Vy)`, полученный из случайного угла и случайной скорости
в диапазоне `[2; 5]`. Так как список-владелец — тот же самый объект `List<Point>`, что
хранится в `_currentPoints` или в `Shape.Points`, изменение точки по индексу сразу
отражается в отрисовке. На каждый тик `Timer` (`MoveTimer_Tick`, интервал 30 мс, скорость
не связана с интервалом) сначала проверяется, не выйдет ли хоть одна точка за границы
`DrawingPanel` при текущем направлении; если выходит по X — знак `Vx` меняется у всех точек,
если по Y — знак `Vy` меняется у всех точек, после чего точки одновременно сдвигаются уже с
обновлёнными скоростями. Отдельный множитель `_speedFactor` (изменяется клавишами `+`/`-`)
масштабирует величину смещения за тик, не трогая интервал таймера, — то есть скорость,
как и требуется, реализована именно через величину смещения.

*Решение, принятое самостоятельно:* в задании не уточняется, входят ли уже сохранённые
фигуры в общее движение или движется только текущая (несохранённая) фигура. Я решил
включать в движение все точки на экране — и текущей, и сохранённых фигур, — так это
выглядит физически цельно (все видимые точки — часть одной "сцены") и не оставляет часть
фигур статичной без явной причины.

**Сдвиг стрелками (С1).** Реализован через переопределение `ProcessCmdKey`, а не через
`KeyDown` — потому что WinForms перехватывает стрелки как клавиши навигации фокуса ещё до
`KeyDown`, особенно когда фокус находится на одной из кнопок; `ProcessCmdKey` вызывается
раньше и позволяет надёжно поймать нажатие в любом состоянии фокуса. По тем же
соображениям, что и в движении, стрелки сдвигают точки и текущей, и всех сохранённых фигур
одновременно. Пока включён режим движения, обработка стрелок отключается (проверка
`!_isMoving`), как и требует вариант.

**Остальные клавиши.** `Space`, `+`/`-`/(включая `NumPad +`/`-`) и `Esc` обрабатываются в
`MainForm_KeyDown` (форма имеет `KeyPreview = true`, поэтому получает событие раньше
дочерних элементов). Для `Space` дополнительно выставляется `e.SuppressKeyPress = true`,
чтобы пробел не "нажимал" повторно кнопку, находящуюся в фокусе.

**Перетаскивание точек мышью.** `DrawPanel_MouseDown` сначала проверяет, не попал ли клик
рядом с уже существующей точкой (радиус попадания больше радиуса самой точки — чтобы было
проще попасть), причём поиск идёт по текущей фигуре и по сохранённым фигурам в обратном
порядке (последняя сохранённая — "сверху"). Если точка найдена — запоминаются
список-владелец и индекс, и начинается перетаскивание; иначе, если включён режим «Точки»,
координаты клика добавляются как новая точка. `MouseMove` при активном перетаскивании
подставляет новые координаты по сохранённому индексу, `MouseUp` сбрасывает перетаскивание.
Во время движения (Д4) перетаскивание и добавление новых точек намеренно отключены, чтобы
не конфликтовать с анимацией.

**Кнопка «Сохранить» (Р1).** `SaveCurrentShape` копирует `_currentPoints` вместе с текущим
режимом отображения и текущими цветами в новый объект `Shape`, добавляет его в
`_savedShapes` и очищает `_currentPoints` — дальше пользователь кликами формирует уже новую
фигуру.

**Очистка.** Кнопка «Очистить» и клавиша `Esc` вызывают один и тот же метод `ClearAll`:
останавливают движение, если оно было включено, и полностью очищают и текущую фигуру, и
список сохранённых.

### Внешний вид

Слева — вертикальная панель с девятью кнопками управления и подсказкой по горячим
клавишам, справа (`Dock = Fill`) — область рисования `DrawingPanel` с включённой двойной
буферизацией (через `SetStyle`, так как `Panel` не даёт настроить это иначе без
наследования).

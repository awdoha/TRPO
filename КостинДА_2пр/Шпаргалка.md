# Шпаргалка по защите практической работы №2 — MusicCatalog

Классы, наследование, перегрузка операторов, коллекции, JSON. Вариант 4: `VariantCalculator.Compute('К','Д') = (1050 + 1044) % 11 = 4`.
Защита лабы ~7 минут; лабы и билеты сдаются раздельно. В переписке группы конкретных вопросов по практике 2 нет — ниже вопросы «на вырост».

**Ссылки вида `файл:строка` даны по ОРИГИНАЛЬНЫМ файлам без комментариев** в `D:\ТРПО\КостинДА_2пр` (там номера строк «чистые»). В комментированной копии `D:\ТРПО(1)\КостинДА_2пр` тот же код, но строки сдвинуты из-за комментариев — там ищите по имени метода/класса (`Ctrl+T` или `Ctrl+F` в VS Code). Проект: `D:\ТРПО\КостинДА_2пр\пр2\ConsoleApp1\`.

## 6. Готовый рассказ на 1–2 минуты

«Моя работа — консольный каталог музыкальных групп, вариант 4: его считает `VariantCalculator.Compute` (Utils\VariantCalculator.cs:7), вызывается из `Main` (Program.cs:8). Id выдаёт статический счётчик `_nextId` (Domain\MusicBand.cs:5) в конструкторе (Domain\MusicBand.cs:18). Наследников два: `RockBand` (Domain\RockBand.cs:3) и `PopBand` (Domain\PopBand.cs:3). У каждого своя характеристика — `HasLiveAlbums` (Domain\RockBand.cs:6) у рока и `IsGirlGroup` (Domain\PopBand.cs:6) у попа — и своя реализация абстрактного свойства `AlbumCount` (объявлено в Domain\MusicBand.cs:16, переопределено в Domain\RockBand.cs:8 и Domain\PopBand.cs:8). `RockBand` запечатан — `sealed` (Domain\RockBand.cs:3). Вывод строки — переопределённый `ToString` (Domain\MusicBand.cs:55, Domain\RockBand.cs:24, Domain\PopBand.cs:24), это полиморфизм.

`MusicBand` и `Artist` реализуют `IComparable` и `IEquatable`: `CompareTo` у группы (Domain\MusicBand.cs:35) сравнивает альбомы, затем название, у артиста (Domain\Artist.cs:30) — стаж `Score` (Domain\Artist.cs:28), затем ключ `Key` (Domain\Artist.cs:25). ## 7. Вопросы преподавателя

### Что уже спрашивали у одногруппников

- «В чём разница, если пишем `override` у метода или просто пишем без `override`?» — одногруппник «поплыл». Подробный ответ ниже (вопрос 1). Больше конкретных вопросов по практике 2 в переписке нет.

### Что ещё могут спросить (короткие ответы)

**1. Разница между `override` и методом без `override` (`new`/сокрытие).**
`override` заменяет реализацию виртуального метода: вызов определяется по **реальному типу объекта** во время выполнения. Метод без `override` (если в базе он `virtual`, компилятор даст предупреждение CS0114 и считает это `new`) лишь **скрывает** базовый: вызов определяется по **типу переменной**. Пример:
```csharp
MusicBand b = new RockBand(...);   // переменная — базовый тип, объект — RockBand
Console.WriteLine(b);              // вызывает ToString()
```
Если в `RockBand` метод с `override` — напечатается версия RockBand («... Концертные альбомы: Да»). Если бы там было `new string ToString()` без `override`, `Console.WriteLine(object)` вызвал бы `object.ToString()` по виртуальной таблице и напечатал бы базовую строку `MusicBand` без «Концертные альбомы». Для `abstract`-члена без `override` программа вообще не скомпилируется (наследник не реализовал контракт).
Где в проекте: `abstract AlbumCount` — `MusicBand.cs:16`, `override` — `RockBand.cs:8`, `PopBand.cs:8`; `override ToString` — `MusicBand.cs:55`, `RockBand.cs:24`, `PopBand.cs:24`; `override Equals`/`GetHashCode` — `MusicBand.cs:45,46`. `virtual DisplayName` (`MusicBand.cs:33`) — виртуальный, но наследники его не переопределяют: пример «можно, но не обязательно». Примеров `new` (сокрытия) в проекте нет.

**2. `abstract` vs `virtual` vs интерфейс.**
`abstract` — член без реализации, наследник **обязан** переопределить; класс с таким членом сам абстрактный (`MusicBand.cs:3,16`). `virtual` — есть реализация по умолчанию, переопределять можно, но не обязательно (`MusicBand.cs:33`, `Artist.cs:25`). Интерфейс — только контракт без состояния; класс может реализовать несколько интерфейсов, а наследовать только один класс (`IComparable`, `IEquatable` — `MusicBand.cs:3`). Абстрактный класс выбираем, когда есть общие данные и код (Name, Genre, Id), интерфейс — когда нужен только набор умений.

**3. Зачем `sealed`?**
Запретить наследование (`RockBand.cs:3`): класс задуман как конечный, нельзя нарушить его инварианты в потомках; плюс небольшая оптимизация вызовов. `PopBand` не запечатан — расширять можно. Также `sealed` у `BandByNameComparer`, `ConsoleApp`, `record MusicBandRepositoryStats`, DTO.

**4. Зачем `GetHashCode` при перегрузке `==`/`Equals`?**
Правило .NET: равные объекты обязаны давать одинаковый хэш. Иначе `Dictionary`/`HashSet` не найдут объект (сначала ищут по хэшу). Поэтому `Equals` и `GetHashCode` у `MusicBand` оба по `Id` (`MusicBand.cs:44,46`), у `Artist` оба по `Key` (`Artist.cs:38,40`). Компилятор даёт предупреждение, если перегружен `==`, а `Equals`/`GetHashCode` нет.

**5. `IComparable` vs `IComparer`.**
`IComparable<T>` реализует сам класс — «естественный порядок» одного вида (`MusicBand.CompareTo`, `MusicBand.cs:35`: альбомы, затем название); используется `_bands.Sort()` (`MusicBandRepository.cs:45`). `IComparer<T>` — отдельный класс-«судья» для любого другого порядка (`BandByNameComparer`, `Compare` — `BandByNameComparer.cs:11`), передаётся в `Sort(comparer)` (`MusicBandRepository.cs:43`). Так можно сортировать по-разному, не меняя `MusicBand`.

**6. Что такое индексатор?**
Свойство с параметром: обращение через `[]`. У репозитория два: `this[int]` (позиция) и `this[string]` (название, бросает `KeyNotFoundException`, если нет) — `MusicBandRepository.cs:12,15`. Оба перегружены по типу параметра. В меню напрямую не вызываются — демонстрация возможности.

**7. Почему для JSON нужны DTO?**
У `MusicBand` абстрактный тип, get-only свойства и конструкторы с проверками — сериализатор не знает, какой подкласс создавать и как вызвать конструктор. DTO — простые классы с `get; set;`. `Type` хранит имя подкласса, `FromDto` (`RepositoryFileStore.cs:113`) по нему через `switch` создаёт `RockBand` или `PopBand`. Поля `HasLiveAlbums`/`IsGirlGroup` — `bool?`, потому что нужны только одному типу. Ещё DTO отделяет формат файла от модели: можно менять одно, не трогая другое.

**8. Зачем `record` для статистики?**
`record MusicBandRepositoryStats` (`MusicBandRepository.cs:93`) — короткая запись неизменяемого класса «только данные»: компилятор генерирует конструктор, свойства, `Equals`, `ToString`. Удобнее кортежа — у полей есть имена (`s.Total`, `s.AverageAlbumCount`), см. `ConsoleApp.cs:171-176`. `record` — ссылочный тип.

**9. Как работает `Equals` по `Id`?**
Две ссылки считаются «равными», если у групп одинаковый `Id` (`MusicBand.cs:44`); имя и жанр не участвуют. Поэтому `List.Remove(band)` (`MusicBandRepository.cs:37`) находит группу по `Id`, а `Add` не даёт добавить дубликат Id (`:21`). Id выдаётся счётчиком `_nextId++` (`MusicBand.cs:30`), а при загрузке из JSON берётся сохранённый.

**10. Где в работе полиморфизм?**
Все группы лежат в `List<MusicBand>`, но каждая ведёт себя по-своему: `ToString` (`ListAll`, `ConsoleApp.cs:76`), `AlbumCount` в `CompareTo` (`MusicBand.cs:35`), в `GetStats` (`MusicBandRepository.cs:82`) и в `ToDto`. Код работает с базовым типом, а нужная версия метода выбирается по реальному типу объекта. Ещё пример — переменная `MusicBand band` в `AddBandInteractive` (`ConsoleApp.cs:83`), в которую кладётся то `RockBand`, то `PopBand`.

**11. Почему сравнение `Artist` идёт по `Score`, а равенство по `Key`?**
Порядок (`CompareTo`, `Artist.cs:30`) — по стажу, потом по `Key`, чтобы порядок был однозначным. Равенство — по `Key` = «ИМЯ|ГОД» в верхнем регистре (`Artist.cs:25,38`); этот же ключ нужен в JSON, чтобы не дублировать артистов (`RepositoryFileStore.cs:51`).

**12. Что будет, если ввести неверные данные?**
Конструкторы бросают `ArgumentException`/`ArgumentOutOfRangeException`, `int.Parse` — `FormatException`; общий `catch` в `ConsoleApp.Run` печатает «Ошибка: ...» и цикл продолжается (`ConsoleApp.cs:22-41`).

### SOLID честно

- **S (единственная ответственность) — в основном соблюдено.** Модель, хранение в памяти, JSON, консольный UI и расчёт варианта разнесены по классам (`Domain`, `Repository`, `Storage`, `UI`, `Utils`). Слабое место: `ConsoleApp` сам и читает ввод, и печатает вывод, а `MusicBandRepository` помимо хранения считает статистику.
- **O (открытость/закрытость) — частично.** Новый способ сортировки добавляется без правки репозитория — достаточно нового `IComparer` (`BandByNameComparer.cs:5`). - **L (подстановка Лисков) — соблюдено.** `RockBand` и `PopBand` можно использовать везде, где ожидается `MusicBand`; `CompareTo`, `Equals`, `ToString` работают корректно для обоих типов. Оговорка: `FromDto` для неизвестного `Type` молча создаёт `PopBand` (`RepositoryFileStore.cs:118`).
- **I (разделение интерфейсов) — не проверяется на своих интерфейсах.** Собственных интерфейсов в проекте нет; используются маленькие стандартные (`IComparable`, `IEquatable`, `IComparer`), что соответствует принципу.
- **D (инверсия зависимостей) — нарушено.** `ConsoleApp` создаёт `new MusicBandRepository()` (`ConsoleApp.cs:10`) и вызывает статический `RepositoryFileStore` — зависимость от конкретных классов, а не от абстракций. Частично в духе принципа только `SortBy(IComparer<MusicBand>)` (`MusicBandRepository.cs:43`): метод зависит от интерфейса.

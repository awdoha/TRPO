## Практика 1. Технология рефлексии для анализа типов в C#

**Задание преподавателя.** Разработать консольное приложение, которое с помощью рефлексии (`System.Reflection`) анализирует типы .NET: показывает имя, пространство имён, сборку, методы, свойства, поля, конструкторы произвольного типа, а также общую статистику по всем типам, загруженным в домен приложения. Часть анализа зависит от индивидуального варианта.

**Мой вариант — 4.** По варианту реализованы (класс `TypeUtils`): поиск метода с наибольшим числом заглавных букв в имени (`GetMethodWithManyCaps`), поиск типа с наибольшим числом закрытых (`private`) полей (`GetTypeWithMaxPrivateFields`), подсчёт числа типов с открытыми нестатическими не-константными полями (`CountTypesWithPublicFields`). Дополнительно по клавише `M` методы выбранного типа группируются по имени со сводкой количества параметров у каждой перегрузки.

**Что реализовано.** Консольное меню: общая статистика по всем загруженным типам, просмотр конкретного типа из списка (`uint`, `int`, `long`, `float`, `double`, `char`, `string`, `record`, `Tuple<int,string>`), настройка цветов консоли. Устойчивость к `ReflectionTypeLoadException` при переборе сборок.

## Практика 3. Работа с 2D-графикой в WinForms

**Задание преподавателя.** WinForms-приложение для работы с двумерной графикой: добавление точек по щелчку мыши, перетаскивание точек, построение фигур по точкам (замкнутая кривая, ломаная, кривые Безье, заполненная кривая), режим анимационного «движения» точек с отражением от границ формы, управление с клавиатуры (`Space`, `+`/`-`, `Esc`, стрелки). Часть функциональности (как именно движутся точки, как настраиваются параметры отображения, как реагируют стрелки, что означает «сохранение») зависит от варианта, вычисляемого по формуле `V = (int(c1) + int(c2)) % 10` от первых букв фамилии и имени на латинице.

**Мой вариант — V = 3** (`'K'`=75, `'D'`=68, `(75+68)%10=3`) → функции **Д4 / П2 / С1 / Р1**:
- **Д4** — у каждой точки своё случайное направление и скорость, выбранные один раз при старте движения; при столкновении с краем формы хотя бы одной точки — направление меняют *все* точки сразу (реализовано как честная инверсия знака нужной составляющей скорости у всех точек, а не полная переслучайновка).
- **П2** — цвет точек и линии настраиваются в отдельном окне через выпадающий список (`ComboBox`), без системного `ColorDialog`.
- **С1** — стрелки сдвигают всю фигуру целиком; не работают во время движения.
- **Р1** — режим «Сохранение»: отдельная кнопка фиксирует текущую фигуру в списке сохранённых, новые точки формируют уже новую фигуру.

**Что реализовано.** Полностью, все пункты задания 1–6: параметры формы, 9 кнопок управления, обработчики кнопок/клавиш (`KeyDown` + `ProcessCmdKey` для стрелок), перетаскивание точек мышью, движение через `Timer` (скорость — через величину смещения, не через интервал). Сборка — 0 ошибок, 0 предупреждений.

## Практика 4. Технология LINQ для обработки файлов

**Задание преподавателя.** Реализовать 4 вычислительные задачи анализа файлов в заданной папке — двумя способами каждую: с использованием `System.Linq` и без единого метода из `System.Linq` (только циклы). Задействовать паттерн «Стратегия»: общий интерфейс (`ITextFileSolver` или `IFileInfoSolver`, в зависимости от варианта) и два класса-решателя (`LinqSolver`, `NoLinqSolver`). Решение — два проекта: библиотека с решателями (`Lab4.Solvers`) и WinForms-приложение для экспериментов (`Lab4.UI`) с табличным и графическим выводом результата. Методы не должны бросать исключения — при невозможности решить задачу возвращается значение по умолчанию.

**Мой вариант — В1.2** (по официальной ведомости курса), интерфейс `ITextFileSolver`, методы:
1. `GetPopularCharPair` — самая частая пара подряд идущих символов по всем файлам (без учёта регистра, пары не пересекают границу строк).
2. `GetLongWords` — N самых длинных слов по всем файлам (все вхождения, устойчивая сортировка).
3. `GetFileWithManyCommonWords` — файл с наибольшим суммарным числом вхождений «общеупотребимых» слов (слово общее, если встречается ≥K раз в каждом файле).
4. `GetPunctuationDistribution` — распределение частот знаков пунктуации, упорядоченное по возрастанию.

**Что реализовано.** Три проекта: `Lab4.Solvers` (интерфейс + `LinqSolver` + `NoLinqSolver`), `Lab4.UI` (WinForms: выбор папки/решателя/задачи/параметров, `DataGridView` + собственноручно нарисованная столбчатая диаграмма на `PictureBox`), `Lab4.Tests` (19 юнит-тестов на xUnit, в т.ч. проверка идентичности результатов LINQ- и не-LINQ-решателей и корректной обработки граничных случаев без исключений). `dotnet build` — 0 ошибок; `dotnet test` — 19/19 пройдено.

**Задание преподавателя.** Веб-приложение на ASP.NET Core MVC с основной и связанной сущностью, хранением через Entity Framework Core, репозиторием за интерфейсом, строго типизированными представлениями и фиксированным набором методов контроллеров (`All`, `Add`, `Edit`, `Remove`, `Details`, `Stat`, `Export`, и `Filter`/`Test` в зависимости от группы вариантов). Вариант вычисляется по формуле `V = (C1 + C2) % 14` от первых букв имени и фамилии на русском языке.

**Мой вариант — В3.1** (`'Д'`=1044, `'К'`=1050, `(1044+1050)%14=8` → индекс 8 = В3.1), приложение **Notes** (заметки): основная сущность `Note` (заголовок, описание, дата, список категорий), связанная сущность `Category`, связь многие-ко-многим. Фильтрация — по варианту В3.1 используется OR-логика: заметка подходит, если хотя бы одно из заданных слов встречается в заголовке или описании.

**Что реализовано.** Полный уровень «до 100%»: работа через Entity Framework Core (провайдер **SQLite** — сознательная замена MS SQL Server, обоснование в `О_РАБОТЕ.md`), CRUD в полном объёме для обеих сущностей (Note и Category), репозиторий `EFNoteRepository` за интерфейсом `INoteRepository`, дедупликация при добавлении, статистика (`Stat`), экспорт в JSON (`Export`), фильтрация с OR-логикой (`Filter`). Приложение реально запущено и все основные маршруты проверены через `curl` (200 OK, без необработанных исключений), а также вручную протестирован полный сценарий CRUD с выбором категорий.
